# 锐捷伙伴资料中心 · Partner Hub

面向海外渠道伙伴与销售的营销资料应用。提供响应式资料库、场景包、收藏与投标清单、附件预览与下载、资料需求和站内通知，以及员工专用的内容维护和发布审核台。

## 运行

使用 Node.js 22.15+ 或 24。依赖及样例 PDF 已随项目锁定，构建不需要访问任何业务系统。

```bash
npm ci
npm test
npm start
```

启动后分别访问两个地址。

| 应用 | 本地入口 | 私有体验站 |
| --- | --- | --- |
| 营销资料中心（销售和伙伴） | http://localhost:3000 | https://ruijie-partner-materials-hub.dimpledcedar.chatgpt.site |
| 资料管理端（内部员工） | http://localhost:3001 | https://ruijie-materials-admin.dimpledcedar.chatgpt.site |

管理端首页先向共享服务校验权限。使用试用模式时，可在访问验证页选择资料编辑或审核身份。正式门户模式使用员工 SSO 和后台角色授权。原资料详情、场景包、消息链接继续从资料中心访问。旧的 `#/studio` 入口转往管理端。

两个浏览器应用有独立的 HTML、JavaScript 和发布产物。分别运行 `npm run build:portal` 和 `npm run build:admin` 可单独更新 `dist/server/index.js`（资料中心及共享 API）和 `dist/admin/index.js`（管理端和 API 代理）。`npm run build` 同时构建两端。管理端独立发布时将其产物作为该站点的 `dist/server/index.js`，使用 `hosting/admin/.openai/hosting.json`。本地可用 `--port` 和 `--admin-port` 修改端口，管理端默认比资料中心大 1。

本地两端共用项目目录的 `.runtime/local.sqlite`。线上仅资料中心服务绑定业务存储，管理端代理到同一 API。部署时为资料中心设置 `ADMIN_ORIGIN`，为管理端设置 `PORTAL_ORIGIN`。私有 Sites 上游的服务访问令牌放在管理端密钥 `PORTAL_SERVICE_TOKEN`。生产启用同一门户 SSO，两入口须能取得门户会话（如由 SSO 网关分别下发），并使用一致的 `PC_COOKIE_NAME`。服务令牌与用户会话分别校验。

私有试用站的新浏览器默认使用同一试用资料库。升级前有独立试用空间的浏览器可从资料中心用员工身份在头像菜单选择「打开资料管理端」，将两个入口配对到原空间。此配对仅用于试用身份；正式门户使用统一业务空间。`SHARED_DEMO_SPACE` 是资料中心服务端为共享试用空间配置的 UUID，`DEMO_PAIRING=true` 仅在这两个受信任的试用站点配置。

### 升级已有本地部署

在原项目目录停止旧服务，拉取代码，运行 `npm ci`、`npm run build`，再运行 `npm start -- --shared`。请保留原来的 `.runtime/local.sqlite`。如果只有一个旧浏览器空间，服务会复用其中的附件、草稿和发布记录；如有多个，启动命令会列出每个空间的资料名称和待审核数量。用 `npm start -- --workspace 空间编号` 选择编辑曾使用的那一个。选择会记住，今后正常 `npm start` 即可。其余旧空间仍保存在原数据库中。可用 `npm start -- --list-workspaces` 查看列表。

本地共享试用空间使用可切换的示例身份，请仅对受信任的试点人员开放。正式门户模式继续使用服务端认证、授权和独立的数据空间。前后台应访问同一服务与同一数据库。

附件上传完成后，请在资料表单点「提交审核」；只上传附件或只保存草稿时，审核队列中不会出现该条目。另一位授权审核人发布后，具有附件查看权限的伙伴即可搜索。已打开的审核台或资料库在窗口重新获得焦点或下一次轮询时读取更新。

## 资料运营后台

员工进入「资料维护台 → 资料管理」。「工作台 → 运营待办」可以直接打开个人待整理附件、待受理需求、发布审核，以及已退回、30 天内到期、已过期或引用证据需复核的资料。台账支持按名称、附件名、负责人、资料类型、BG 和状态查找。到期当天仍有效。

| 运营环节 | 操作 |
| --- | --- |
| 找回上传文件 | 在「待整理附件」用原编辑身份找到文件，点「继续建档」。系统带入实际原件和上传时的有效查看、下载范围。补上简介后保存草稿或送审。关闭页面前未保存的标题、简介等字段需重新填写。 |
| 制作与送审 | 编辑选归属 BG，填写分类和类型字段，配置资料及附件权限。保存草稿后可以继续编辑。提交审核后进入对应 BG 的审核队列。 |
| 审核与退回 | 另一位授权审核人核对附件、授权范围及换版变化。退回必须说明原因，编辑能从「已退回」进入修改并重新提交。 |
| 查阅档案 | 在台账点「资料档案」，可看当前附件及各自授权、有效期和按时间倒序展示的流转记录。新版自写入起记录发布版本、编辑、审核人及文件名。旧数据只显示能关联的既有记录。 |
| 换版、到期及撤回 | 编辑已发布资料并送审。审核通过后替换发布版。已过期资料可修改有效期再送审。下架需填写原因，伙伴随后无法搜索或下载。 |
| 需求交付 | 在需求池认领、分派或要求补充，可关联已发布资料，也可按需求制作。批准后核对需求人的实际文件权限和用途，符合条件时通知领取。 |

**本地数据位置。** 从项目根目录启动时，附件原件、预览、资料元数据、权限、需求和审核记录都保存在该目录的 `.runtime/local.sqlite`。上传文件名是元数据，原件以二进制存放在数据库中。重新部署请保留此文件。停服后复制整个 `.runtime` 目录可备份本地实例。找不到历史资料时，先核对运行目录、数据库及工作空间，再用原编辑身份查看待整理附件或台账。

## 用户、业务角色与权限

维护台分为工作台、内容管理、需求管理、流程管理和系统管理。登录人的授权决定可见分组、菜单及按钮。角色配置使用应用支持的菜单与操作目录。内置角色可查阅，自定义角色可创建和修改。

在本地共享运行包中，可从头像菜单选择「平台管理员 · 系统管理」。正式环境从门户取得身份、组织、账号状态和有效签约关系。已登录的用户会登记到本应用目录，完整名单可从门户分页同步。

1. 在「系统管理 → 角色管理」新建业务角色，选择前台及后台能力，核对可见菜单。「菜单权限」可按前台、后台入口反查对应操作权限及角色。
2. 在「用户管理」搜索姓名、组织或用户 ID。选择用户和 BG，勾选该 BG 下的全部角色并保存。每个 BG 独立计算多角色权限并集。显式保存空角色可撤销该 BG 的应用权限，下载还需匹配原有附件授权。
3. 在「流程管理 → 审批流程」配置角色节点或人员节点。送审时按目录校验每个节点至少有一名有效候选人。审批时再次检查账号、角色、BG、提交人和节点。角色调整、离职或停用后，原节点可能无人可办，流程管理员可在「在途审批」指定合格接收人并记录原因。
4. 在「权限诊断」选择账号和资料，查看发布状态、菜单权限、附件预览和下载条件。授权、转派及下架可在操作记录或资料档案中追溯。

门户 reviewer 默认取得审批权限。流程配置须单独授权。试用账号许晴兼任渠道运营和流程管理，顾言具备产品经理角色。系统管理员由部署配置指定；BG 用户管理员可在负责 BG 分配普通业务角色，管理类授权和全局角色定义由平台管理员维护。产品、方案和类型为共享目录。

## 按产品、方案和类型配置审批

1. 有目录维护权限的人员在「内容管理 → 分类与类型」维护产品、方案和资料类型目录。编辑在资料上选择对应条目。
2. 在「审批流程 → 新增流程」选择归属 BG、匹配条件和优先级。空条件表示全部，填写多个条件时必须同时满足。同一 BG 启用流程的优先级唯一，数值小的先匹配。
3. 依次添加审批节点，每步可指定业务角色、指定账号，或交给该 BG 任一审核人。选业务角色时，拥有该 BG 角色和节点审批权限的任一成员可处理。在正式门户中，指定账号填用户 ID，启用时使用门户用户目录确认该账号有相应 BG 的审核权限。本地共享试用可分别选择顾言（产品审核）和许晴（发布审核）。
4. 编辑送审前可看到预计流程。提交后系统保存当时的节点和顺序。中间节点通过后状态仍是「待审核」，最后节点通过后才发布和交付。审核人可以勾选「仅待我审核」。提交人不能自审。
5. 任一节点退回时记录原因。编辑修改后重新送审，按当前规则从第一步开始。调整或停用规则不改变在途审批。无匹配规则及升级前已经待审的资料继续走标准单节点审核。可配置流程适用于资料新发和换版，场景包沿用独立审核。

## 走一遍真实交付流程

1. 伙伴搜索资料并提交需求，勾选是否需要下载、对客外发。
2. 从头像菜单切换到“资料编辑”，打开“需求池”，认领并选择“按需求制作资料”。上传附件，设置用途与受众，勾选交付附件后送审。
3. 切换到另一名“发布审核”人员，在“发布审核”中预览并通过。对无法交付给需求人的附件，后台会保留需求为处理中。
4. 切回伙伴，打开消息或“我的需求”领取资料。再次打开、预览、下载都会按当前账号权限检查。
5. 可在维护台另行维护资料类型、专属字段、场景包，或将资料换版、下架。收藏和任务清单会跟踪有效版本。

## 工程与接入

- 前端采用 Vue 2.7.16、Vuex 3.6.2 和 vue-i18n 6.1.3，与已核实的海外 Partner Center 前端版本一致。支持手机、桌面和中英文导航；资料正文按发布语言展示。
- 服务端使用标准 Fetch API。托管版本通过私有 R2 绑定 `BUCKET` 保存状态、文件和预览；本地适配器使用 SQLite。试点的审核、交付和消息写入使用同一次条件更新；并发更新会重试。扩大用户量时应将按试点存储的业务状态拆为正式平台的关系数据表和队列。
- 接口包括读取当前用户可见内容的 `GET /api/state`、提交业务操作的 `POST /api/actions`、员工上传的 `POST /api/upload`，以及服务端鉴权的附件与封面访问。可见范围由一条完整的身份、BG、区域、签约国家和伙伴类型共同判定。
- 附件限 8 MB。PDF、DOCX、PPTX、TXT 提供文字预览，图片生成独立预览件。扫描版 PDF、加密或无法提取文字的文件需上传可预览版本。原件必须获得下载授权。演示空间做格式与大小检查；正式会话模式要求扫描服务返回通过。
- 内置样例 PDF 已提交。若修改种子内容，可使用 Python、ReportLab 和 `scripts/seed-pdf.py` 重新生成对应 PDF。照片来源见 [图片说明](docs/photos.md)。

### 正式 Partner Center 联调

以下是本应用约定的适配接口。门户方需要提供和验证真实接口映射；此仓库不包含锐捷凭据或生产地址。

| 设置 | 用途 |
|---|---|
| `PC_ADMIN_IDS` | 平台管理员的门户用户 ID，多个用逗号分隔。初次接入选用具备有效 BG 的员工账号。 |
| `PC_USERS_URL` | 可选的 HTTPS 分页目录。平台管理员在用户管理中同步，采用服务令牌鉴权，GET 首次不带 cursor，后续带 cursor。返回 `{"users":[...],"next_cursor":null}`，每个用户沿用会话档案字段。停用账号需返回 active=false。 |
| `DEMO_MODE=false` | 禁用演示身份选择。生产域名应在发布前显式配置。 |
| `PC_SESSION_URL`、`PC_COOKIE_NAME` | 后端将门户会话令牌送往受信任的 HTTPS 校验服务。返回当前用户的 `id/name/role/org/active/grants`；角色为 partner、sales、editor 或 reviewer；每一组 grants 对应一条有效签约关系，包含 bg、region、country（ISO 两位国家代码）和 channel（门户伙伴类型代码）。active 为 false 的关系不参与匹配；缺少国家的关系仅能匹配不限国家的规则。每次业务请求重新校验。 |
| `PC_DIRECTORY_URL`、`PC_SERVICE_TOKEN` | 交付离线用户前按 ID 查询其当前有效身份和归属。无可靠结果时保留待交付。 |
| `SCAN_URL`、`SCAN_TOKEN` | 附件以二进制 POST 至可信扫描服务，仅在返回成功且 JSON 为 `{"clean":true}` 后保存。 |
| 门户菜单、语言、消息 | 从门户菜单接入，支持 `?lang=zh` 或 `?lang=en`。本应用内消息可用；前台在窗口获得焦点时及每 30 秒检查新消息。配置 PC_MESSAGE_URL 后，通过 HTTPS POST 向门户消息适配器交付待发通知；接收方以 Idempotency-Key 去重，返回 2xx 表示已持久接收。请求或定时触发会重试失败消息，无人访问时应由部署平台配置定时触发器。真实消息协议需由门户方映射并联调。 |

在集成环境核对门户登录与停用、单点退出、语言、管理角色、文件存储及通知，并用真实授权矩阵抽验后再导入业务资料。试点在打开消息时显示已收藏或列入清单的资料在未来 30 天内的到期提醒。

### 国家与伙伴类型权限

在「新增资料／编辑资料 → 伙伴访问权限」分别维护查看组、下载组。组内的国家、伙伴类型支持多选，同一条有效签约须满足所有维度。各组取并集。上传前在「本次上传的附件权限」选择继承或为本批文件单独设置国家、区域和伙伴类型。上传接口会立即校验并保存规则，上传后可逐份收紧；修改须审核后生效。历史规则缺少 country 时沿用不限国家，原 BG、区域和渠道限制继续生效。

正式门户的员工会话在 `audienceCatalog.partnerTypes` 中返回 `[{value,label}]`，value 与签约的 channel 一致。可选的 `audienceCatalog.countries` 使用同样结构，未提供时显示标准国家列表。会话与收件人目录的 grants 使用同一字段约定。正式环境不使用演示伙伴类型；历史已选代码可保留。

验收示例：查看组设「泰国 × 经销商」和「越南 × 系统集成商」，下载组仅设后一组。演示身份林悦可预览，越南集成商可下载。在受众模拟中选择「东南亚、泰国、系统集成商」，应显示完全隐藏。
